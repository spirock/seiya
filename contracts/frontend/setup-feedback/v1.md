# Feedback del asistente · incremento funcional acotado

El asistente mantiene los seis assets frozen/v1 intactos. Un complemento JS
nuevo muestra el mensaje de revisión al lado del botón que la solicita y lleva
la aprobación a la vista. No reemplaza diseño, framework ni el formulario.

Motivación: el estado original se muestra al inicio de un panel desplazable;
al revisar desde abajo, un error de rutas puede quedar fuera de la vista y
parecer que no ocurre nada. El navegador también puede bloquear submit por un
campo required antes de cualquier POST. Ambos casos necesitan feedback local.

Solo DOM/textContent y eventos de la UI: sin peticiones adicionales, lectura de
config, inferencias, guardado ni cambios de permisos. Mensajes nativos de rutas
reciben explicación legible, conservando el error técnico. required se enfoca
sin reenviar automáticamente. Aprobación visible no equivale a start autorizado.

La acción «Desactivar imágenes en este borrador» vacía ID/rutas de imagen solo
tras clic y emite input para invalidar aprobación previa. No toca rutas/modelos
de texto, catálogo, historial, backend, pesos ni configuración persistida.
El backend sigue rechazando rutas/roles no válidos; no implementar un bypass
«continuar» cuando no exista un motor compatible. No tocar OpenCode.
